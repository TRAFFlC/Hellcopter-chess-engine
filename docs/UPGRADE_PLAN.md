## 0. 前提：三个必须正视的事实

1. **消融实验"失败"是正常现象，且已被记录在案**（EXPERIMENTS.md:20260719_merge_delete_cgi_failed）：
   单独关掉某模块 ≈ 0 Elo，合并删除多个模块 → −50 Elo 退化。原因：**搜索模块存在冗余补偿**。
   推论：**"单独关掉不降 → 可删"的消融逻辑在搜索模块间不成立**。后续实验禁止基于单模块消融做批量删除决策。

2. **合并后的引擎是多条实验线的叠加混合物**（本地基线 + 上游评估减法 + 上游时间管理 5 连发 + KRK/KQK + SEE 修复）。
   其中**上游的评估减法（删 P3 机动性 / P4 Hanging / P5 威胁 / P6 残局开关）没有经过"当前引擎"整体 T2 确认**
   ——上游 Week7 合并是"进行中"状态（EXPERIMENTS.md 20260718_week7_merge_confirm 判定: 待 SPRT 结论）。
   **合并后的第一个任务不是加功能，而是复检合并产物本身**。

3. **编译器状态未知**：GOAL.md 记录 gcc 无法启动（沙箱限制）。所有 C 源码改动挂在编译确认后。
   升级规划必须区分"纯参数（运行时 JSON）"与"源码改动（需编译）"两类。

## 3. Phase 1：TT 工程代差 + 静态分复用（2000→2250 主通道）

来自 Goldfish（SF 式 TT）/ Facon（按需计算）/ Reckless（评估桶化）三代证据，全部是**源码改动**（需编译），按侵入度排序：

| # | 改动 | 预期 | 风险 |
|---|---|---|---|
| 1.1 | **静态评估按需计算**：negamax 只在剪枝深度阈值内调 evaluate()（深节点零评估成本） | 低风险提速 → 深度↑ | 极低（Facon search.cpp:1007 验证形态） |
| 1.2 | **TT 着法合法性验证**：对着法生成表逐项比对（Facon 形态，~10 行） | 修哈希污染 | 极低，三引擎一致做法 |
| 1.3 | **TT 条目加 eval 字段**（或独立评估缓存）：QS stand-pat 复用 | 搜索提速 + 剪枝更准 | 中（结构改动；Pepito/Goldfish/Invictus 三引擎一致最优信号） |
| 1.4 | **杀分 50 步降级 + GHI 防护**（halfmove≥90 禁 TT 截止） | 和棋纪律 | 低（Goldfish tt.rs:473-501 形态） |

**实验纪律**：每一项单独 T1 快筛（300 局 10+0.2 SPRT），仅单项通过才进下一项；**禁止 1.1-1.4 合并打包测试**（消融教训：混合改动无法归因）。

## 4. Phase 2：全量 Texel 调参（2500→2800 主通道，纯参数）

Facon 实证：934 权重 Texel 全量重调 = +250 Elo（1.5→1.6 零搜索改动）。本项目已有 texel_tuner.py 管线。

**前置（必须先行）**：
- 2.0 调查输棋大类，先修确定性缺陷（如果有）再调参，否则调参会把缺陷学进权重
- 2.1 用 `trace` 式线性系数分解验证"评估 = 权重 × 特征"恒等式成立（Facon trace_evaluate 思想）
  ——调参前先证明管线一致性。可参考 tuning/texel_report.py 现状补强

**主实验**：
- 2.2 从 eval_weights 全量（PST mg/eg 对 + 各特征组）一次送 Texel，不手工逐项
- 2.3 校验训练数据多样性：自对弈数据混入外部大师对局（CLAUDE.md Texel 修复段已指出）
- 2.4 调后 T1 快筛确认 ≥ +3 Elo（否则数据或目标函数有问题，回查管线）
- 2.5 注意与上游评估减法矛盾：如果 0.3 已回滚评估减法，此处以"恢复后的全评估"为调参对象

**不重复验证的负结果**（Facon README rejected 段，2800 级实测）：
- Tarrasch 车置通路兵后（−9）、非线性机动性（−12）、Kaufman 材料不平衡（≈0）——不需花 A/B 预算

## 5. Phase 3：参数置信度与 LMR 家族收尾（纯参数）

- 3.1 LMR 参数重扫必须在 **当前 scale60 环境**（教训：7 月网格跑在 scale300 上已失效，GOAL.md 记录）
- 3.2 优先单独重测：SEE 阈值（depth_scale 60→300 挂起项）、NMP 深度下限、history decay
- 3.3 时间管理（合并自上游的 5 连发）：以 96+0.8 目标时制单独确认，不并入参数打包
- 3.4 禁止：多参数联合调节一次打包测试（归因能力归零）

## 7. 变体兼容（Reckless 报告结论，挂起项）

- chess324 门槛极低：王车标准位 → 现有易位/搜索直接可用，只需 FEN 解析健壮
- 真正的差距是 PST 开局先验污染（只影响陌生排布下的评估直觉，不影响 96+0.8 标准棋标定）

## 8. 实验纪律（本规划红线）

1. **一次只改一组相关参数**（CLAUDE.md §实验隔离）
2. **禁止基于单模块消融做批量删除**（20260719 教训，EXPERIMENTS.md）
3. 任何源码改动先 T0 回归，再 T1 快筛，单项通过才进下一项
4. 借鉴留痕：任何来自研究引擎的实现（TT eval 字段 / 按需评估 / 杀分降级）在 EXPERIMENTS.md 记"参考来源"
5. 资源纪律：并发 ≤4，启动前记录资源预算（GOAL.md §3.0）
6. 编译恢复前：源码改动全部挂起，只做纯参数实验；状态在 GOAL.md §五 快照
